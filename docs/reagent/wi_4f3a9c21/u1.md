# u1 — Add macOS package-desktop GitHub Actions workflow

## Goal

Create `.github/workflows/package-desktop.yml` — a new CI workflow that builds and packages the Electron desktop app for macOS (both arm64 and x64), uploading the resulting `.dmg` and `.zip` artifacts. No existing files are modified.

## Scope

The executor is allowed to touch exactly one file:

- `.github/workflows/package-desktop.yml`

The following files MUST NOT be modified:

- `.github/workflows/ci.yml`
- `desktop/electron-builder.yml`
- Any file under `bridge/`, `desktop/src/`, or anywhere else in the repo.

## Approach

### 1. Create `.github/workflows/package-desktop.yml`

The full intended YAML content is specified below. Write it verbatim (modulo YAML whitespace equivalence).

```yaml
name: Package Desktop

on:
  push:
    tags:
      - 'v*'
  workflow_dispatch:

jobs:
  package-mac:
    runs-on: macos-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: |
            bridge/package-lock.json
            desktop/package-lock.json

      # Step 1: Install and compile the bridge
      - name: Install bridge deps
        working-directory: bridge
        run: npm ci

      - name: Build bridge
        working-directory: bridge
        run: npm run build

      # Step 2: Slim the bridge — remove devDependencies before bundling
      - name: Prune bridge dev deps
        working-directory: bridge
        run: npm prune --omit=dev

      # Step 3: Install and compile the Electron main-process TypeScript
      - name: Install desktop deps
        working-directory: desktop
        run: npm ci

      - name: Build desktop
        working-directory: desktop
        run: npm run build

      # Step 4: Package — both macOS architectures; never publish to a registry
      - name: Package macOS (arm64 + x64)
        working-directory: desktop
        run: npx electron-builder --mac --x64 --arm64 --publish never

      # Step 5: Upload all .dmg and .zip files produced under desktop/out
      - name: Upload macOS installers
        uses: actions/upload-artifact@v4
        with:
          name: reagent-mac
          path: |
            desktop/out/*.dmg
            desktop/out/*.zip
          if-no-files-found: error
```

### Key design decisions

- **Triggers**: `push` on tags matching `v*` and `workflow_dispatch` only. The workflow does NOT fire on every push or pull_request, keeping it separate from the existing `ci.yml` which runs on branch pushes/PRs.
- **Node 22**: LTS at time of implementation; matches approved direction (not 20, which `ci.yml` still uses).
- **cache-dependency-path**: multi-line value covers both `bridge/package-lock.json` and `desktop/package-lock.json` so npm cache is keyed correctly across both workspaces.
- **Bridge slimming**: `npm prune --omit=dev` in `bridge/` is run after `npm run build` and BEFORE `desktop/npm ci`. This ensures that when `electron-builder` copies `../bridge/node_modules/**` (per `electron-builder.yml` `extraResources` filter) it copies only production deps, not dev tooling.
- **electron-builder flags**: `--mac --x64 --arm64` produce all four artifacts declared in `desktop/electron-builder.yml` under the `mac` target (dmg x64, dmg arm64, zip x64, zip arm64). `--publish never` prevents any attempt to push a release.
- **Artifact upload**: `if-no-files-found: error` makes the step fail visibly if electron-builder produced no output, instead of silently uploading an empty artifact.
- **Unsigned builds**: No code-signing secrets, entitlements, or notarization steps are included. This is an explicit non-goal for this work item.
- **Windows/Linux**: Not included. `desktop/electron-builder.yml` already declares those targets for future activation.

## Acceptance criteria

1. A file exists at `.github/workflows/package-desktop.yml` after the change.
2. `git diff --name-only` shows exactly one new file: `.github/workflows/package-desktop.yml`. No other files are modified.
3. The workflow YAML is valid — `python3 -c "import yaml, sys; yaml.safe_load(sys.stdin)" < .github/workflows/package-desktop.yml` exits 0 (or `actionlint` if available passes with no errors).
4. The `on:` block contains only `push.tags: ['v*']` and `workflow_dispatch` — no `push.branches` or `pull_request` triggers.
5. The single job is named `package-mac` and specifies `runs-on: macos-latest`.
6. `actions/setup-node@v4` step sets `node-version: 22` (not 20) and includes `cache-dependency-path` referencing both `bridge/package-lock.json` and `desktop/package-lock.json`.
7. The bridge build sequence appears in order: `npm ci` → `npm run build` → `npm prune --omit=dev`, all with `working-directory: bridge`.
8. The desktop build sequence appears in order: `npm ci` → `npm run build`, both with `working-directory: desktop`.
9. The packaging step runs `npx electron-builder --mac --x64 --arm64 --publish never` with `working-directory: desktop`.
10. The artifact upload step uses `actions/upload-artifact@v4`, `path` covers `desktop/out/*.dmg` and `desktop/out/*.zip`, and `if-no-files-found: error` is set.
11. `.github/workflows/ci.yml` and `desktop/electron-builder.yml` are byte-for-byte unchanged.
