# u2 — PWA favicon, manifest icons, and Fastify icon route

## Goal

Wire the brand assets produced by u1 into the bridge PWA: add a favicon to the HTML
page, populate the previously-empty `icons` array in `manifest.webmanifest` with the
192 and 512 PNG icons (plus a maskable variant), and add a `/favicon.ico` (and
`/icons/*.png`) route to the Fastify server so the browser can actually fetch them.

## Scope

Files the executor is allowed to create or edit:

```
bridge/src/web/manifest.webmanifest
bridge/src/web/index.html
bridge/src/http/server.ts
```

The executor MUST NOT create or modify any file under `assets/` (that is u1's scope),
but MAY read files there to copy PNGs into the `bridge/src/web/` subtree.

Specifically, the icons to be served live at a new path:
```
bridge/src/web/icons/favicon-16.png
bridge/src/web/icons/favicon-32.png
bridge/src/web/icons/icon-192.png
bridge/src/web/icons/icon-512.png
bridge/src/web/icons/icon-maskable-512.png
```

These PNG files are in scope for this unit (they are copies of the outputs from
`assets/icons/`, committed into the web tree so Fastify can serve them statically
without any build step).

## Approach

### 1. Copy PNG icons into the web tree

Copy from `assets/icons/` (built by u1's `assets/build.sh`):

```
cp assets/icons/favicon-16.png bridge/src/web/icons/favicon-16.png
cp assets/icons/favicon-32.png bridge/src/web/icons/favicon-32.png
cp assets/icons/icon-192.png   bridge/src/web/icons/icon-192.png
cp assets/icons/icon-512.png   bridge/src/web/icons/icon-512.png
cp assets/icons/icon-maskable-512.png bridge/src/web/icons/icon-maskable-512.png
```

Commit these PNG files; they are the runtime-served versions. The `assets/` originals
remain the regeneration source.

### 2. Update `bridge/src/web/index.html`

Add two `<link>` tags inside `<head>` immediately after the existing
`<link rel="manifest" ...>` line:

```html
<link rel="icon" type="image/png" sizes="32x32" href="/icons/favicon-32.png" />
<link rel="icon" type="image/png" sizes="16x16" href="/icons/favicon-16.png" />
```

Do NOT touch any CSS, JS, or structural HTML. The header text "reagent" and all inline
styles must remain unchanged.

### 3. Update `bridge/src/web/manifest.webmanifest`

Replace the current `"icons": []` with:

```json
"icons": [
  {
    "src": "/icons/icon-192.png",
    "sizes": "192x192",
    "type": "image/png"
  },
  {
    "src": "/icons/icon-512.png",
    "sizes": "512x512",
    "type": "image/png"
  },
  {
    "src": "/icons/icon-maskable-512.png",
    "sizes": "512x512",
    "type": "image/png",
    "purpose": "maskable"
  }
]
```

No other fields in the manifest change.

### 4. Update `bridge/src/http/server.ts`

The existing static-file serving block (lines 139-148) uses a typed `for...of` over
an array of `[route, file, type]` tuples. Extend it to serve the icon files.

The cleanest approach is to add a wildcard GET route for `/icons/:filename` that reads
from the `webDir/icons/` subdirectory. Insert this route after the existing SSE route
and before the static-file loop:

```typescript
app.get("/icons/:filename", async (req, reply) => {
  const { filename } = req.params as { filename: string };
  // Only allow the specific PNG files we ship to prevent path traversal.
  const allowed = new Set([
    "favicon-16.png",
    "favicon-32.png",
    "icon-192.png",
    "icon-512.png",
    "icon-maskable-512.png",
  ]);
  if (!allowed.has(filename)) return reply.code(404).send({ error: "not found" });
  reply.type("image/png");
  return readFileSync(join(webDir, "icons", filename));
});
```

`readFileSync` and `join` are already imported. No new imports needed.

Alternatively, add `/favicon.ico` by redirecting to the 32px PNG:

```typescript
app.get("/favicon.ico", async (_req, reply) => {
  return reply.redirect("/icons/favicon-32.png", 302);
});
```

Add this redirect route just above the `/icons/:filename` route.

## Acceptance criteria

1. `bridge/src/web/icons/` contains exactly five PNG files:
   `favicon-16.png`, `favicon-32.png`, `icon-192.png`, `icon-512.png`,
   `icon-maskable-512.png`.
2. `bridge/src/web/index.html` contains two new `<link rel="icon">` tags pointing to
   `/icons/favicon-32.png` and `/icons/favicon-16.png`. No other change to the file.
3. `bridge/src/web/manifest.webmanifest` has `"icons"` populated with three entries
   (192, 512, maskable-512). No other field changed.
4. `bridge/src/http/server.ts` has a `/icons/:filename` route with an allowlist check,
   and a `/favicon.ico` → `/icons/favicon-32.png` redirect. TypeScript compiles without
   errors (`cd bridge && npm run build` passes).
5. Starting the bridge (`npm run dev` from `bridge/`) and visiting
   `http://localhost:4319/icons/icon-192.png` returns a PNG with Content-Type
   `image/png`. Visiting `/favicon.ico` redirects to `/icons/favicon-32.png`.
6. No file outside the scope list is created or modified. `assets/` is untouched.
