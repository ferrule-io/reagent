# u3 — Desktop app icon (.icns) and tray icon

## Goal

Replace the placeholder 16x16 tray icon and the absent app icon with real brand assets
in the Electron desktop package. Wire `app.icns` into `electron-builder.js` so packaged
builds use it, and replace `desktop/build/tray-icon.png` with the crisp 16 px + 32 px
(@2x) variants from u1.

## Scope

Files the executor is allowed to create or edit:

```
desktop/build/tray-icon.png
desktop/build/tray-icon@2x.png
desktop/build/icon.icns
desktop/electron-builder.js
desktop/src/main.ts
```

The executor MUST NOT create or modify any file under `assets/` (u1's scope) or under
`bridge/` (u2's scope). It may read from `assets/icons/` to copy files.

## Approach

### 1. Copy icons into desktop/build/

```
cp assets/icons/tray-icon.png    desktop/build/tray-icon.png
cp assets/icons/tray-icon@2x.png desktop/build/tray-icon@2x.png
cp assets/icons/app.icns         desktop/build/icon.icns
```

`desktop/build/tray-icon.png` is already tracked by git (77 bytes, 16x16 placeholder).
Overwrite it in place.

`desktop/build/icon.icns` is new — create it. electron-builder automatically picks up
`build/icon.icns` from the `buildResources: 'build'` directory for macOS app icons
(no further config needed for that path).

### 2. Update `desktop/electron-builder.js`

electron-builder 24 automatically uses `<buildResources>/icon.icns` for the macOS app
icon when the file exists at `build/icon.icns`. However, to be explicit and
self-documenting, add the `icon` key to the `mac` section:

```js
mac: {
  icon: 'build/icon.icns',   // <-- add this line
  category: 'public.app-category.developer-tools',
  // ... rest unchanged
}
```

The path is relative to `buildResources` (`build/`), so the value is `'build/icon.icns'`
(electron-builder resolves it from the project root, not from buildResources).

No other change to `electron-builder.js`.

### 3. Update `desktop/src/main.ts` for @2x tray icon

Electron on Retina displays uses `@2x` suffix convention for high-DPI tray icons.
The `Tray` constructor already receives the path from `trayIconPath()`. Update that
function to pass the base path and let Electron resolve @2x automatically — Electron
does this automatically when the @2x file is alongside the 1x file:

```typescript
function trayIconPath(): string {
  if (app.isPackaged) {
    return path.join(process.resourcesPath, 'tray-icon.png');
  }
  return path.join(__dirname, '..', 'build', 'tray-icon.png');
}
```

This function is UNCHANGED. Electron automatically loads `tray-icon@2x.png` from the
same directory when it exists. No code change needed for @2x resolution.

However, the `extraResources` block in `electron-builder.js` only copies
`build/tray-icon.png` to the packaged app. Add `tray-icon@2x.png` to that block:

```js
extraResources: [
  {
    from: '../bridge',
    to: 'bridge',
    filter: ['dist/**', 'node_modules/**', 'package.json', 'package-lock.json'],
  },
  {
    from: 'build/tray-icon.png',
    to: 'tray-icon.png',
  },
  {
    from: 'build/tray-icon@2x.png',   // <-- add this entry
    to: 'tray-icon@2x.png',
  },
],
```

This is the only additional change to `electron-builder.js` beyond the `mac.icon` key.

### 4. Verify TypeScript compiles

After editing `electron-builder.js` (CommonJS, not TypeScript), verify that
`desktop/src/main.ts` still compiles: `cd desktop && npx tsc --noEmit`. No changes
to `main.ts` are strictly required (Electron handles @2x automatically), but if there
is a type error, fix it.

## Acceptance criteria

1. `desktop/build/tray-icon.png` is a 16x16 PNG containing the brand mark (not the
   original 77-byte placeholder). `file desktop/build/tray-icon.png` reports PNG, 16x16.
2. `desktop/build/tray-icon@2x.png` exists and is a 32x32 PNG.
3. `desktop/build/icon.icns` exists. `file desktop/build/icon.icns` reports
   "Apple Icon Image data".
4. `desktop/electron-builder.js` has `mac.icon: 'build/icon.icns'` and an
   `extraResources` entry for `tray-icon@2x.png`.
5. `desktop/src/main.ts` compiles without TypeScript errors (`npx tsc --noEmit` in the
   `desktop/` directory passes).
6. No file outside the scope list is created or modified.
