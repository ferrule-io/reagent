# u3 — Per-unit status badges on unit cards (app.js)

## Goal
In app.js, add a per-unit status badge (pending / running / passed / failed) to
each unit card in the "Units of work" section, derived by scanning the activity
log for `unit <unitId>: ...` lines. No backend, no transport changes.

## Scope
This unit owns, in `bridge/src/web/app.js`:
1. The **"Units of work" block** inside `renderJobPage` (currently lines
   ~263–309, the `if ((it.units || []).length > 0) { ... unitsSection ... }`
   block) — modify the per-unit `<li class="unit-item">` rendering to add a
   status badge next to `.unit-title`.
2. A NEW helper appended in the "Shared helpers" region (near `formatTs`), named
   to avoid collision with u2's helpers:
   - `deriveUnitStatus(unit, log)` → returns `"pending" | "running" | "passed" |
     "failed"` by scanning `log` for lines mentioning this unit's id.

This unit MUST NOT modify the "Full activity log" block (~326–352), the
current-activity banner, or any of u2's helpers (`classifyLogLine`,
`buildActivityBanner`, `roleBadgeEl`, `verdictPillEl`). This unit MUST NOT modify
`bridge/src/web/index.html` (CSS is u1). Do not edit list-page or stepper code.

## Approach
1. Write `deriveUnitStatus(unit, log)`:
   - Determine the unit identifier to match. Units carry `title`, `scope`,
     `dependsOn`, `planDocPath`. Derive the unit id from `planDocPath`
     (e.g. basename without `.md`, like `u1`) and/or from a `unit.id` field if
     present; match log lines of the form `unit <id>: ...`.
   - Scan `log` (array of `{ at, line }`) for lines referencing this unit id:
     - `unit <id>: review PASS` → `"passed"`.
     - `unit <id>: review FAIL` → `"failed"`.
     - `unit <id>: execution complete` (without a later FAIL) → treat as
       `"running"` until a review verdict arrives, or `"passed"` if no review
       step is expected — choose `"running"` as the intermediate state and let a
       later `review PASS/FAIL` line override it.
     - any other `unit <id>: ...` line → `"running"`.
     - no matching line → `"pending"`.
   - Process log in order so the LAST relevant line wins (passed/failed override
     running).
2. In the units block, for each `unit` compute
   `const status = deriveUnitStatus(unit, it.log || []);` and create
   `<span class="unit-status status-<status>">` with a capitalized label; append
   it to the `<li>` alongside `unitTitle` (e.g. right after the
   `li.appendChild(unitTitle)` call). Keep all existing `.unit-*` elements and
   classes intact.
3. Use `textContent` for the status label. No innerHTML injection.

## Acceptance criteria
- `git diff` for this unit touches ONLY `bridge/src/web/app.js`.
- New function `deriveUnitStatus` exists; does not collide with u2 helpers.
- Each rendered `.unit-item` includes a `.unit-status` element with exactly one
  of `status-pending` / `status-running` / `status-passed` / `status-failed`.
- The "Full activity log" block (~326–352) and the current-activity banner /
  u2 helpers are byte-for-byte unchanged in this unit's diff.
- Emitted class names match selectors defined by u1. No new network/transport
  code; relies on the existing SSE re-render.
