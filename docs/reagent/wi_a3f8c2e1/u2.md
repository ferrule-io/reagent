# u2 — Log classification + role/verdict badges + current-activity banner (app.js)

## Goal
In app.js, parse the existing activity-log lines to (a) render a role badge
(Planner / Executor / Reviewer / Orchestrator) and a PASS/FAIL verdict pill on
each activity-log entry, and (b) render a prominent "current activity" banner
near the top of the job page derived from the most recent log line. No backend,
no transport changes — relies on the existing SSE re-render in `init()`.

## Scope
This unit owns, in `bridge/src/web/app.js`:
1. The **"Full activity log" block** inside `renderJobPage` (currently lines
   ~326–352, the `if ((it.log || []).length > 0) { ... logSection ... }` block) —
   only the rendering of each `<li class="log-entry">` is modified to inject the
   role badge + verdict pill.
2. A NEW insertion point near the TOP of `renderJobPage`: the **current-activity
   banner**, appended immediately AFTER the phase stepper line
   `main.appendChild(buildStepper(it.phase));` (line ~208) and BEFORE the
   "Labeled fields" block. Insert exactly one `main.appendChild(...)` for the
   banner here.
3. NEW helper functions appended in the "Shared helpers" region (after
   `formatTs`, near line ~434), named to avoid collision with u3:
   - `classifyLogLine(line)` → returns `{ role, verdict }` where `role` is one of
     `"planner" | "executor" | "reviewer" | "orchestrator" | null` and `verdict`
     is `"pass" | "fail" | null`.
   - `buildActivityBanner(it)` → returns the banner element (or null/empty when
     there is no log).
   - `roleBadgeEl(role)` and `verdictPillEl(verdict)` → return badge/pill elements
     (return null when arg is null).

This unit MUST NOT modify the "Units of work" block (lines ~263–309) — that is
u3's region. This unit MUST NOT modify `bridge/src/web/index.html` (CSS is u1).
Do not edit `buildStepper`, `card`, or list-page code.

## Approach
1. Write `classifyLogLine(line)` using the conventional formats from the
   approved direction (case-insensitive substring/regex matching):
   - Reviewer: line contains `review:` / `review PASS` / `review FAIL` /
     `plan review:` or matches `unit <id>: review PASS|FAIL`.
   - Planner: contains `units decomposed`, `plan decomposed into`, or
     `decomposed into N units`.
   - Executor: matches `unit <id>: execution complete` OR free-form executor
     summaries — classify executor conservatively (e.g. lines mentioning
     `execution` / `executing unit`). Prefer Orchestrator for orchestration verbs.
   - Orchestrator: `approved — delegating`, `starting investigation`,
     `proposal ready`, `delegating`, etc. Use as the default/fallback role when
     no other role matches, OR return `null` to render no badge — pick one and
     be consistent (recommend Orchestrator as fallback only for clear orchestration
     verbs, else `null`).
   - Verdict: `PASS` → `"pass"`, `FAIL` → `"fail"` (match on review lines).
   Keep matching order so review lines win the Reviewer role even though they may
   contain `unit <id>:`.
2. `roleBadgeEl(role)`: create `<span class="role-badge role-<role>">` with the
   capitalized role label; return null when role is null.
   `verdictPillEl(verdict)`: create `<span class="verdict-pill verdict-<verdict>">`
   with text `PASS`/`FAIL`; return null when verdict is null.
3. In the activity-log block, for each entry call `classifyLogLine(entry.line)`,
   then prepend the role badge (if any) before the `.log-line` span and append
   the verdict pill (if any) after it. Keep the existing `.log-ts` and
   `.log-line` elements and their classes intact; use `textContent` for the line
   (no raw HTML injection).
4. `buildActivityBanner(it)`: take the LAST entry of `it.log`. Build
   `<div class="activity-banner">` containing `.activity-banner-label`
   (e.g. the classified role label, or "Activity") and `.activity-banner-text`
   (the last line, via `textContent`). If the phase is terminal (DONE / one of
   TERMINAL_ERROR) or there is no log, render an idle/empty banner or skip — use
   the `.activity-banner.idle` class for the idle case. Append it right after the
   stepper as specified in Scope.
5. Verify the existing SSE handler re-renders the job page on each `item` event
   (it calls `renderJobPage`), so the banner and badges update live with no
   transport change. No edits to `init()` are required or permitted here.

## Acceptance criteria
- `git diff` for this unit touches ONLY `bridge/src/web/app.js`.
- New functions `classifyLogLine`, `buildActivityBanner`, `roleBadgeEl`,
  `verdictPillEl` exist; names do not collide with any u3-introduced helper.
- The current-activity banner is appended immediately after
  `main.appendChild(buildStepper(it.phase));` and before the labeled-fields block.
- Each `.log-entry` renders a `.role-badge` (when a role is inferred) and review

- The "Units of work" block (~263–309) is byte-for-byte unchanged in this unit's
  diff (owned by u3).
- All emitted class names match selectors defined by u1; banner/badge text is set
  via `textContent` (no innerHTML of log content). No new network/transport code.
