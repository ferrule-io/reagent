# u1 — Use Electron's embedded Node to spawn the bridge

## Goal

Fix the macOS GUI launch failure where `spawn('node', ...)` cannot find `node` on the
minimal PATH that Finder/Dock hands to GUI processes. Replace the bare `'node'` binary
reference with `process.execPath` (Electron's own embedded Node runtime) and set the
`ELECTRON_RUN_AS_NODE=1` environment variable so the Electron binary behaves as a plain
Node process. Update README.md to retire the now-obsolete "node on PATH" prerequisite and
remove the "Bundled Node runtime" follow-up item (the need it described is now solved).

## Scope

- `desktop/src/main.ts`
- `desktop/README.md`

No other files may be touched. `electron-builder.yml` is explicitly out of scope — no new
resources need to be bundled.

## Approach

### 1. desktop/src/main.ts — `startBridge()`

Locate the two adjacent lines in `startBridge()` (currently lines 36–40):

```typescript
logLines.push(`[INFO] starting bridge: node ${entry}`);
bridgeProcess = spawn('node', [entry], {
  env: { ...process.env },
  stdio: ['ignore', 'pipe', 'pipe'],
});
```

Replace them with:

```typescript
logLines.push(`[INFO] starting bridge: ${process.execPath} (ELECTRON_RUN_AS_NODE) ${entry}`);
bridgeProcess = spawn(process.execPath, [entry], {
  env: { ...process.env, ELECTRON_RUN_AS_NODE: '1' },
  stdio: ['ignore', 'pipe', 'pipe'],
});
```

Rationale for applying unconditionally (not gated on `app.isPackaged`):
- In dev mode `process.execPath` is the Electron dev binary, which also honours
  `ELECTRON_RUN_AS_NODE=1` and exposes the same Node version — so dev and prod are unified.
- A gate adds complexity with no benefit; the approach is correct in both contexts.

No other changes to main.ts.
