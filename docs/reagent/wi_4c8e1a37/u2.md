# u2 — Bridge: assign worktreePath on creation, teardown on terminal state

## Goal

Make the bridge assign a `worktreePath` to each work item at creation time and tear down the git worktree (via `git worktree remove --force`) when a work item reaches a terminal phase (DONE, REJECTED, or FAILED). This is the runtime half of concurrency isolation — each EXECUTE job will find a pre-assigned path ready to use.

## Scope

- `bridge/src/state/store.ts`
- `bridge/src/mcp/server.ts`
- `bridge/src/http/server.ts`
- `bridge/src/index.ts`

## Approach

### Overview

The bridge creates work items in two places:
- `mcp/server.ts` → `register_work_item` tool (terminal/MCP origin)
- `http/server.ts` → `POST /api/items` (phone origin)

And terminates items in one place:
- `mcp/server.ts` → `complete_work_item` tool

The entry point `index.ts` wires all deps together and must be updated to thread `worktreesDir` through.

### 1. `bridge/src/state/store.ts`

Extend `CreateInput` to accept an optional `worktreePath?: string`. In the `create()` method, spread it onto the `WorkItem` the same way `branch` is handled:

```ts
...(input.worktreePath !== undefined ? { worktreePath: input.worktreePath } : {}),
```

This keeps `store.create()` a pure data writer — worktree directory creation is done by the caller.

### 2. `bridge/src/mcp/server.ts`

Add the worktrees path computation. The `McpDeps` interface needs `worktreesDir: string` added. In the `register_work_item` handler, where `store.create()` is called:

1. The existing `node:path` import at line 4 is `import { resolve, isAbsolute } from "node:path"` — `join` is not present. Add it: change the import to `import { resolve, isAbsolute, join } from "node:path"`.
2. The file has no `node:fs` import. Add one: `import { mkdirSync } from "node:fs"`.
3. Compute `worktreePath = join(worktreesDir, id)`.
4. Call `mkdirSync(worktreesDir, { recursive: true })` to ensure the parent directory exists.
5. Pass `worktreePath` to `store.create()`.

In `complete_work_item`, after the `store.update()` call, attempt to remove the worktree if `item.worktreePath` is set:

```ts
const item = store.get(id);
if (item?.worktreePath) {
  try {
    execSync(`git worktree remove --force "${item.worktreePath}"`, {
      cwd: item.repoPath,
      stdio: "ignore",
    });
  } catch {
    // best-effort: worktree may not have been initialized yet (e.g. item failed before EXECUTE)
  }
}
```

Add `import { execSync } from "node:child_process"` at the top. The `--force` flag handles the case where the directory no longer exists or has uncommitted changes.

### 3. `bridge/src/http/server.ts`

The HTTP `POST /api/items` handler also calls `store.create()` with a branch. Mirror the same pattern:

1. Add `worktreesDir: string` to the `HttpDeps` interface.
2. In the handler, compute `worktreePath = join(worktreesDir, id)` and pass it to `store.create()`. `join` is already imported from `node:path` at line 4 (`import { dirname, join } from "node:path"`), so no change to that import is needed.
3. The file has an existing `node:fs` import at line 5: `import { readFileSync } from "node:fs"`. Extend it to `import { readFileSync, mkdirSync } from "node:fs"` — do NOT add a second `node:fs` import. Call `mkdirSync(worktreesDir, { recursive: true })` before computing the path.

The HTTP server does not call `complete_work_item` — terminal transitions go through the MCP tool's `complete_work_item`, so teardown is already covered by step 2 above.

### 4. `bridge/src/index.ts`

In `main()`, pass `worktreesDir: cfg.worktreesDir` into the `mcpDeps` object and into the `buildHttpServer` call. The change is two lines:

```ts
const mcpDeps = { store, registry, checkpoints, checkpointPollMs: cfg.checkpointPollMs, worktreesDir: cfg.worktreesDir };
// ...
const app = buildHttpServer({ store, repos, registry, checkpoints, launcher, worktreesDir: cfg.worktreesDir });
```

## Acceptance criteria

1. `CreateInput` in `store.ts` has `worktreePath?: string`; `store.create()` persists it onto the `WorkItem` when provided.
2. `McpDeps` in `mcp/server.ts` has `worktreesDir: string`.
3. `register_work_item` computes `worktreePath = join(worktreesDir, id)`, calls `mkdirSync(worktreesDir, { recursive: true })`, and passes `worktreePath` to `store.create()`.
4. `complete_work_item` reads the stored `item.worktreePath` and runs `git worktree remove --force <worktreePath>` (in a try/catch) when the field is present.
5. `HttpDeps` in `http/server.ts` has `worktreesDir: string`; `POST /api/items` computes and stores `worktreePath` the same way as the MCP path.
6. `bridge/src/index.ts` passes `worktreesDir: cfg.worktreesDir` to both `mcpDeps` and the `buildHttpServer` call.
7. No other files are modified.
8. `npm run build` inside `bridge/` succeeds without TypeScript errors.
