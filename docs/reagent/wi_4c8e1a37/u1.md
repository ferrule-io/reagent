# u1 — WorkItem type: add worktreePath field + config worktrees dir

## Goal

Extend the `WorkItem` type with an optional `worktreePath` field so the bridge can persist each work item's dedicated git worktree location. Add a `worktreesDir` entry to `Config` so the path (`~/.reagent/worktrees`) is configurable and derived in one place.

## Scope

- `bridge/src/state/types.ts`
- `bridge/src/config.ts`

## Approach

### 1. `bridge/src/state/types.ts`

Add `worktreePath?: string` to the `WorkItem` interface, immediately after the existing `branch?: string` field (line 55). Keep the same optional pattern. Add a brief JSDoc comment explaining the field:

```ts
/** Absolute path to the git worktree for this item (e.g. ~/.reagent/worktrees/<id>). Assigned alongside branch; torn down on terminal state. */
worktreePath?: string;
```

No changes to `StatusUpdate` are needed — `worktreePath` is infrastructure state managed by the bridge, not reported by agent sessions.

### 2. `bridge/src/config.ts`

Add `worktreesDir: string` to the `Config` interface. In `loadConfig()`, populate it from the env var `REAGENT_WORKTREES_DIR` with a default of `~/.reagent/worktrees` (derived via `join(homedir(), ".reagent", "worktrees")`). Place the new field immediately after `stateDir` so related config is grouped together.

```ts
worktreesDir: process.env.REAGENT_WORKTREES_DIR ?? join(homedir(), ".reagent", "worktrees"),
```

## Acceptance criteria

1. `bridge/src/state/types.ts` contains `worktreePath?: string` in the `WorkItem` interface with a JSDoc comment.
2. `bridge/src/config.ts` has `worktreesDir: string` in the `Config` interface.
3. `loadConfig()` returns `worktreesDir` defaulting to `~/.reagent/worktrees` (using `join(homedir(), ".reagent", "worktrees")`), overridable via `REAGENT_WORKTREES_DIR`.
4. No other files are modified.
5. `npm run build` inside `bridge/` succeeds (TypeScript compiles without errors).
