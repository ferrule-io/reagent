# u4 — bridge HTTP + PWA: wire resolvePluginDir, GET /api/plugin, install hint

## Goal

1. Wire `resolvePluginDir()` (from u3's `bridge/src/plugin-dir.ts`) into
   `bridge/src/index.ts`, replacing the old inline pluginDir one-liner and passing
   the resolved value to both `Launcher` and `buildHttpServer`.
2. Extend `HttpDeps` in `bridge/src/http/server.ts` with `pluginDir?: string` and
   add a `GET /api/plugin` route that returns the resolved dir, its version, and a
   copy-paste marketplace command.
3. Add a plugin-install hint inside `renderListPage()` in `bridge/src/web/app.js`
   (NOT only in `init()`) using a module-level cache variable populated in `init()`.
4. Fix pre-existing TypeScript errors in `bridge/test/http-api.test.ts` (missing
   `worktreesDir` in existing `buildHttpServer` call-sites) and add two new test
   cases for `GET /api/plugin`.

All four changes land together so every commit compiles cleanly. No broken
intermediate state.

## Scope

- `bridge/src/index.ts`
- `bridge/src/http/server.ts`
- `bridge/src/web/app.js`
- `bridge/src/web/index.html`
- `bridge/test/http-api.test.ts`

## Approach

### 1. `bridge/src/index.ts` — wire resolvePluginDir

The current file (line 33-34) has:
```ts
const pluginDir =
  process.env.REAGENT_PLUGIN_DIR ?? join(dirname(fileURLToPath(import.meta.url)), "..", "..");
```
and the `buildHttpServer` call (line 40) does NOT pass `pluginDir`.

Replace with:

```ts
// At the top of the file, add the import:
import { resolvePluginDir } from "./plugin-dir.js";

// In main(), replace the one-liner with:
const pluginDir = await resolvePluginDir();

// Update buildHttpServer call to pass pluginDir:
const app = buildHttpServer({
  store, repos, registry, checkpoints, launcher,
  worktreesDir: cfg.worktreesDir,
  pluginDir,
});
```

Since `HttpDeps.pluginDir` is optional (added in step 2), this compiles even
if u4's `server.ts` change is applied in the same commit (which it is — both
changes land together within this unit).

Remove the now-unused `dirname` and `fileURLToPath` imports ONLY if they are not
referenced elsewhere in `index.ts`. Check the file before removing — `dirname`
and `fileURLToPath` are NOT used anywhere else in the current `index.ts`, so they
can be dropped.

### 2. `bridge/src/http/server.ts` — add `pluginDir?` to HttpDeps and route

Add `pluginDir?: string` to the `HttpDeps` interface:

```ts
export interface HttpDeps {
  store: StateStore;
  repos: RepoStore;
  registry: Registry;
  checkpoints: CheckpointStore;
  /** Optional: when present, phone-submitted work is launched and re-launched on approval. */
  launcher?: SessionLauncher;
  worktreesDir: string;
  /** Optional: resolved plugin directory (set in packaged mode). */
  pluginDir?: string;
}
```

In `buildHttpServer`, destructure `pluginDir` from `deps` and add the route
immediately after the other `/api/` routes (before the SSE route or static
file serving):

```ts
const { store, repos, registry, checkpoints, launcher, worktreesDir, pluginDir } = deps;

// ... existing routes ...

app.get("/api/plugin", async () => {
  const dir = pluginDir ?? null;
  let version: string | null = null;
  if (dir) {
    try {
      const pj = join(dir, ".claude-plugin", "plugin.json");
      version = (JSON.parse(readFileSync(pj, "utf8")).version as string) ?? null;
    } catch { /* ignore */ }
  }
  const marketplaceAddCommand = dir ? `/plugin marketplace add ${dir}` : null;
  return { pluginDir: dir, version, marketplaceAddCommand };
});
```

`readFileSync` and `join` are already imported in `server.ts` (lines 5 and 3
respectively). No new imports are needed.

### 3. `bridge/src/web/app.js` — plugin install hint in renderListPage

**Critical constraint**: `renderListPage()` does `main.innerHTML = ""` on every
call (line 126-127). Any DOM node created outside this function is destroyed on
every render. The install hint MUST be built inside `renderListPage()` on each
render, reading from a module-level cache variable that `init()` populates once.

#### 3a. Module-level cache variable

At the top of `app.js`, alongside `const items = new Map()` and `let repos = []`,
add:

```js
let pluginInstallCmd = null; // populated by init(), consumed by renderListPage()
```

#### 3b. Populate the cache in `init()`

In `init()` (around line 821), fetch `/api/plugin` alongside the existing calls:

```js
async function init() {
  const [itemsRes] = await Promise.all([fetch("/api/items"), loadRepos()]);
  for (const it of await itemsRes.json()) items.set(it.id, it);

  // Fetch plugin install command once; stored in module-level cache for renderListPage.
  try {
    const pluginRes = await fetch("/api/plugin");
    if (pluginRes.ok) {
      const { marketplaceAddCommand } = await pluginRes.json();
      if (marketplaceAddCommand) pluginInstallCmd = marketplaceAddCommand;
    }
  } catch (_) {}

  route();
  // ... SSE setup unchanged ...
}
```

Do NOT manipulate DOM here. Only set the module-level variable.

#### 3c. Render the hint inside `renderListPage()`

In `renderListPage()` (around line 124), after the existing `main.appendChild(itemsDiv)`
call, conditionally append the install-hint section:

```js
function renderListPage() {
  const main = document.querySelector("main");
  main.innerHTML = "";

  main.appendChild(reposPanel());

  const newWork = newWorkForm();
  main.appendChild(newWork);

  const itemsDiv = document.createElement("div");
  itemsDiv.id = "items";
  [...items.values()]
    .sort((a, b) => b.updatedAt.localeCompare(a.updatedAt))
    .forEach((it) => itemsDiv.appendChild(card(it)));
  main.appendChild(itemsDiv);

  // Plugin install hint — only shown when server reports a marketplaceAddCommand.
  if (pluginInstallCmd) {
    const section = document.createElement("section");
    section.id = "plugin-install";
    section.style.marginTop = "16px";

    const details = document.createElement("details");
    const summary = document.createElement("summary");
    summary.textContent = "Install plugin in Claude Code";
    details.appendChild(summary);

    const desc = document.createElement("p");
    desc.style.cssText = "font-size:13px;color:var(--text-muted);margin:8px 0 4px";
    desc.textContent =
      "Run this command inside a Claude Code session to install the reagent plugin:";
    details.appendChild(desc);

    const code = document.createElement("code");
    code.style.cssText =
      "display:block;background:var(--surface);border:1px solid var(--border);" +
      "border-radius:var(--radius);padding:8px 10px;font-size:13px;" +
      "color:var(--warm-code);word-break:break-all";
    code.textContent = pluginInstallCmd;
    details.appendChild(code);

    section.appendChild(details);
    main.appendChild(section);
  }
}
```

This guarantees the hint is rebuilt on every render and always reflects the
current `pluginInstallCmd` cache value.

### 4. `bridge/src/web/index.html` — no static plugin-install node needed

Because the hint is built programmatically inside `renderListPage()`, there is no
need to add a static `<section id="plugin-install">` to `index.html`. Do NOT add
one. The existing `index.html` structure (which has a skeleton that `app.js`
immediately replaces) is correct as-is.

If no other `index.html` change is needed for this work item, leave the file
untouched and remove it from the git diff. The scope listing includes it as a
permitted file, but the executor should omit it if there are no needed changes.

### 5. `bridge/test/http-api.test.ts` — fix existing errors and add new tests

#### 5a. Fix pre-existing TypeScript errors

The three existing `buildHttpServer(...)` call-sites omit `worktreesDir` (a
required field), causing TypeScript errors introduced by a prior work item. Fix
each call site by adding `worktreesDir: dir` (reuse the `dir` temp-dir variable
that is already in scope in each `beforeEach`):

- Line 25: `app = buildHttpServer({ store, repos, registry: reg, checkpoints: cps, worktreesDir: dir });`
- Line 209: `app = buildHttpServer({ store, repos, registry: reg, checkpoints: cps, worktreesDir: dir });`
- Line 326: `app = buildHttpServer({ store, repos, registry: reg, checkpoints: cps, launcher, worktreesDir: dir });`

#### 5b. Add new test cases for GET /api/plugin

Add a new `describe` block after the existing ones:

```ts
describe("HTTP API — /api/plugin", () => {
  it("returns null fields when pluginDir is not supplied", async () => {
    const tmpDir = mkdtempSync(join(tmpdir(), "reagent-plugin-test-"));
    const s = new StateStore(tmpDir);
    const r = new RepoStore(tmpDir);
    const g = new Registry();
    const c = new CheckpointStore();
    const testApp = buildHttpServer({
      store: s, repos: r, registry: g, checkpoints: c, worktreesDir: tmpDir,
    });
    try {
      const res = await testApp.inject({ method: "GET", url: "/api/plugin" });
      expect(res.statusCode).toBe(200);
      expect(res.json()).toMatchObject({
        pluginDir: null,
        version: null,
        marketplaceAddCommand: null,
      });
    } finally {
      await testApp.close();
      rmSync(tmpDir, { recursive: true, force: true });
    }
  });

  it("returns pluginDir and marketplaceAddCommand when pluginDir is supplied", async () => {
    const tmpDir = mkdtempSync(join(tmpdir(), "reagent-plugin-test-"));
    const s = new StateStore(tmpDir);
    const r = new RepoStore(tmpDir);
    const g = new Registry();
    const c = new CheckpointStore();
    const testApp = buildHttpServer({
      store: s, repos: r, registry: g, checkpoints: c,
      worktreesDir: tmpDir,
      pluginDir: "/some/plugin/root",
    });
    try {
      const res = await testApp.inject({ method: "GET", url: "/api/plugin" });
      expect(res.statusCode).toBe(200);
      const body = res.json();
      expect(body.pluginDir).toBe("/some/plugin/root");
      expect(body.marketplaceAddCommand).toBe(
        "/plugin marketplace add /some/plugin/root",
      );
      // version is null because /some/plugin/root does not exist on disk
      expect(body.version).toBeNull();
    } finally {
      await testApp.close();
      rmSync(tmpDir, { recursive: true, force: true });
    }
  });
});
```

Each test spins up its own server instance and cleans up in `finally`, matching
the defensive style of the surrounding test file.
