# u3 — bridge: plugin-dir resolution helper (exported, no HTTP wiring)

## Goal

Implement the plugin-directory resolution and materialization logic as a standalone
exported module (`bridge/src/plugin-dir.ts`). When `REAGENT_BUNDLED_PLUGIN_DIR`
is set (packaged mode) the helper copies the bundled plugin to `~/.reagent/plugin`
if absent or version-stale, then returns that path. When `REAGENT_PLUGIN_DIR` is
set it returns it directly. Otherwise it falls back to the repo-root dev path.

This unit is entirely self-contained: it does NOT touch `bridge/src/index.ts`,
`bridge/src/http/server.ts`, or any test file. The exported function is consumed
by u4, which owns all `index.ts` and `server.ts` changes. Every intermediate
commit in this unit compiles on its own.

## Scope

- `bridge/src/plugin-dir.ts` (new file)

## Approach

### 1. Create `bridge/src/plugin-dir.ts`

Create a new file with a single exported async function and a private helper:

```ts
import { existsSync, mkdirSync, cpSync, readFileSync } from "node:fs";
import { homedir } from "node:os";
import { dirname, join } from "node:path";
import { fileURLToPath } from "node:url";

/**
 * Resolve the effective plugin directory for this bridge process.
 *
 * Priority:
 *   1. REAGENT_PLUGIN_DIR (explicit override — dev or special deployments)
 *   2. REAGENT_BUNDLED_PLUGIN_DIR (set by Electron main.ts when packaged)
 *      → copies to ~/.reagent/plugin if absent or version-stale
 *   3. Dev-mode fallback: repo root (bridge/dist/index.js → ../../..)
 */
export async function resolvePluginDir(): Promise<string> {
  if (process.env.REAGENT_PLUGIN_DIR) return process.env.REAGENT_PLUGIN_DIR;

  const bundledSrc = process.env.REAGENT_BUNDLED_PLUGIN_DIR;
  if (bundledSrc) {
    const dest = join(homedir(), ".reagent", "plugin");
    if (!existsSync(dest) || pluginVersion(dest) !== pluginVersion(bundledSrc)) {
      mkdirSync(dest, { recursive: true });
      cpSync(bundledSrc, dest, { recursive: true });
    }
    return dest;
  }

  // Dev-mode fallback: this file compiles to bridge/dist/plugin-dir.js,
  // so three levels up (dist → bridge → reagent) is the repo root.
  return join(dirname(fileURLToPath(import.meta.url)), "..", "..");
}

function pluginVersion(dir: string): string {
  try {
    const pj = join(dir, ".claude-plugin", "plugin.json");
    return (JSON.parse(readFileSync(pj, "utf8")).version as string) ?? "";
  } catch {
    return "";
  }
}
```

### 2. Verify compilation

After writing the file, confirm `cd bridge && npx tsc --noEmit` exits 0 for this
new file in isolation. The file has no dependency on `index.ts`, `server.ts`, or
any test infrastructure, so it cannot introduce cross-unit TypeScript errors.

Note: the existing `test/http-api.test.ts` file has pre-existing TypeScript errors

### 3. No other files touched

Do NOT modify `bridge/src/index.ts`, `bridge/src/http/server.ts`, or any test
files. Those belong to u4.

## Acceptance criteria

- A new file `bridge/src/plugin-dir.ts` exists after this unit's commit.
- The file exports exactly one public symbol: `resolvePluginDir(): Promise<string>`.
- The three-branch logic is present:
  - `REAGENT_PLUGIN_DIR` → early return with no I/O.
  - `REAGENT_BUNDLED_PLUGIN_DIR` → copy-if-stale to `~/.reagent/plugin`, return that path.
  - Neither set → return repo-root via `import.meta.url` traversal.
- `pluginVersion()` reads `.claude-plugin/plugin.json` and returns `""` on any error.
- `cpSync` is called with `{ recursive: true }`.
- `git diff --name-only` for this unit's commit shows ONLY `bridge/src/plugin-dir.ts`.
- `cd bridge && npx tsc --noEmit` exits with the same errors as before this unit
  (pre-existing `worktreesDir` test errors — no new errors introduced).
