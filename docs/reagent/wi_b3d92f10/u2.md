# u2 — desktop/main.ts: pass bundled plugin path to bridge via env var

## Goal

When the Electron app is running in packaged mode (`app.isPackaged === true`),
inject the env var `REAGENT_BUNDLED_PLUGIN_DIR` (set to
`path.join(process.resourcesPath, 'plugin')`) into the environment that the
bridge child process is spawned with. In dev mode the env var must be absent so
bridge falls back to its existing repo-root resolution unchanged.

## Scope

- `desktop/src/main.ts`

## Approach

1. Open `desktop/src/main.ts` and locate `startBridge()`.

2. Find the `spawn` call (line 37):
   ```ts
   bridgeProcess = spawn(process.execPath, [entry], {
     env: { ...process.env, ELECTRON_RUN_AS_NODE: '1' },
     ...
   });
   ```

3. Build the extra env object conditionally before the spawn call:
   ```ts
   const extraEnv: NodeJS.ProcessEnv = app.isPackaged
     ? { REAGENT_BUNDLED_PLUGIN_DIR: path.join(process.resourcesPath, 'plugin') }
     : {};
   ```

4. Spread `extraEnv` into the `env` property:
   ```ts
   env: { ...process.env, ELECTRON_RUN_AS_NODE: '1', ...extraEnv },
   ```

5. No other changes. All existing imports (`path`, `fs`, etc.) are already
   present; no new imports are required because `path` is already imported at
   the top of the file.

## Acceptance criteria

- `git diff desktop/src/main.ts` shows the `env` spread in `startBridge()` now
  includes `REAGENT_BUNDLED_PLUGIN_DIR` when `app.isPackaged` is true, and omits
  it otherwise (conditional logic visible in the diff).
- `process.resourcesPath` and `path.join` are used (not hard-coded strings).
- No other logic in `main.ts` is changed (no new menu items, no new imports
  beyond what is already present, no changes to `bridgePath()` or
  `trayIconPath()`).
- TypeScript compiles without error: run `cd desktop && npx tsc --noEmit` (or the
  existing build command) and verify exit code 0.
