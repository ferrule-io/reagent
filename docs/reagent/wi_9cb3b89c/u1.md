# u1 — Add afterAllArtifactBuild hook to sign, notarize, and staple DMG containers

## Goal

The `.app` inside each DMG is already signed and notarized by electron-builder's built-in
notarize path. However, the DMG container itself is never signed or notarized, which means
macOS Gatekeeper may warn when a user opens the disk image (it carries the quarantine bit
from a browser download). This unit adds an `afterAllArtifactBuild` hook to
`desktop/electron-builder.js` that, for each produced `.dmg`, (1) code-signs the DMG with
the Developer ID Application identity, (2) submits it to Apple's notarization service via
`xcrun notarytool submit --wait`, and (3) staples the ticket to it via `xcrun stapler staple`.
The hook is gated on `process.env.APPLE_TEAM_ID` so local / unsigned builds are completely
unaffected.

## Scope

The executor is allowed to touch exactly one file:

- `desktop/electron-builder.js`

No other files in the repo may be modified.

## Approach

### Background

`afterAllArtifactBuild` is an electron-builder 24 lifecycle hook that fires once all
artifacts (`.dmg`, `.zip`, etc.) have been produced and the built-in notarization of the
`.app` has already completed. The hook receives a `BuildResult` object whose `artifactPaths`
property is an array of absolute path strings for every produced artifact.

### Step 1 — Add the hook to `module.exports`

Append `afterAllArtifactBuild` as a new top-level key in the exported config object in
`desktop/electron-builder.js`. The full addition (to be inserted after the `linux: { ... }`
block, before the closing `};`) is:

```js
  afterAllArtifactBuild: async (buildResult) => {
    // Only run when signing credentials are present (CI with secrets).
    // Unsigned local builds skip this entirely.
    if (!process.env.APPLE_TEAM_ID) return;

    const { execFileSync } = require('node:child_process');
    const dmgs = buildResult.artifactPaths.filter((p) => p.endsWith('.dmg'));

    for (const dmg of dmgs) {
      console.log(`[afterAllArtifactBuild] Signing DMG: ${dmg}`);
      execFileSync(
        'codesign',
        [
          '--sign', 'Developer ID Application',
          '--timestamp',
          '--verbose',
          dmg,
        ],
        { stdio: 'inherit' },
      );

      console.log(`[afterAllArtifactBuild] Notarizing DMG: ${dmg}`);
      execFileSync(
        'xcrun',
        [
          'notarytool', 'submit',
          '--apple-id', process.env.APPLE_ID,
          '--password', process.env.APPLE_APP_SPECIFIC_PASSWORD,
          '--team-id', process.env.APPLE_TEAM_ID,
          '--wait',
          dmg,
        ],
        { stdio: 'inherit' },
      );

      console.log(`[afterAllArtifactBuild] Stapling DMG: ${dmg}`);
      execFileSync(
        'xcrun',
        ['stapler', 'staple', dmg],
        { stdio: 'inherit' },
      );
    }
  },
```

### Step 2 — Verify the gate condition

The `if (!process.env.APPLE_TEAM_ID) return;` guard at the top of the hook matches the
existing pattern in the same file (see the `notarize` key). When `APPLE_TEAM_ID` is unset
the hook returns immediately — no shell commands are spawned.

### Step 3 — Verify no workflow change is needed

Read `.github/workflows/package-desktop.yml` to confirm that `APPLE_ID`,
`APPLE_APP_SPECIFIC_PASSWORD`, and `APPLE_TEAM_ID` are already passed as environment
variables to the `Package macOS` step. They are (lines 57-64 of the current file). No
changes to the workflow are needed.

### Important implementation notes

- Use `require('node:child_process')` inside the hook body. Do NOT add a top-level
  `require` — the hook is only invoked in CI; keeping the require local avoids any
  side-effects on local builds where the hook body never executes.
- Use `'Developer ID Application'` as the signing identity string. `codesign --sign`
  accepts a substring of the certificate common name. In CI the keychain contains exactly
  one Developer ID Application certificate (imported from `CSC_LINK` by electron-builder),
  so `codesign` resolves the partial name unambiguously. This is the same pattern used by
  other electron-builder-based projects for post-build DMG signing.
- `--timestamp` is required for Gatekeeper to trust the signature when the DMG is
  distributed (it pins the Apple TSA timestamp into the signature).
- `notarytool submit --wait` blocks until Apple returns `Accepted` or an error. CI minutes
  consumed here are acceptable; failure (non-zero exit) will propagate through
  `execFileSync` and fail the CI step with the Apple error output visible in the log.
- The `stdio: 'inherit'` option forwards stdout/stderr from all spawned commands to the
  electron-builder log, giving full visibility in CI.

## Acceptance criteria

1. `git diff --name-only` shows exactly one modified file: `desktop/electron-builder.js`.
2. The exported object in `desktop/electron-builder.js` contains a key
   `afterAllArtifactBuild` whose value is an `async` function.
3. The hook body begins with `if (!process.env.APPLE_TEAM_ID) return;`.
4. The hook calls `codesign`, `xcrun notarytool submit --wait`, and `xcrun stapler staple`
   (in that order) for each path in `buildResult.artifactPaths` that ends with `.dmg`.
5. The `codesign --sign` argument is the literal string `'Developer ID Application'`
   (partial name) — not a template string incorporating `APPLE_TEAM_ID` or any other
   environment variable.
6. `node -e "require('./desktop/electron-builder.js')"` exits 0 (the file parses as valid
   CommonJS).
7. When `APPLE_TEAM_ID` is unset in the environment and the hook is invoked manually via
   `node -e "require('./desktop/electron-builder.js').afterAllArtifactBuild({artifactPaths:[]})"`,
   it returns without error and without spawning any child processes.
8. The existing `notarize`, `mac`, `win`, `linux`, and all other config keys remain
   unchanged.
